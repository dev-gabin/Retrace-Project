# 추론 활성화 정책

확인일: 2026-10-07

이 문서는 메인 유닛의 PIR 이벤트와 Jetson Nano의 사람 탐지를 이용해 객체 추론을 시작하고 중지하는 기준을 정의한다.
통신 메시지 형식은 [protocol.md](protocol.md), 하드웨어 핀과 전기적 연결은 [pinmap.md](pinmap.md), 실제 장치 검증 항목은 [classroom_test_checklist.md](classroom_test_checklist.md)를 따른다.

전체 동작의 핵심은 다음과 같다.

```text
PIR이 움직임 감지
→ STM32가 Jetson에 이벤트 전송
→ Jetson이 YOLO 추론 시작
→ YOLO가 실제 사람인지 확인
→ 사람이 일정 시간 확인되지 않고 PIR도 LOW이면 추론 대기 상태로 복귀
```

## 1. 기본 원칙

- PIR은 사람 존재를 확정하는 센서가 아니라 적외선 열의 변화를 감지하는 보조 센서다.
- PIR은 Jetson의 추론을 깨우는 시작 신호로 사용한다.
- 실제 사람 여부와 사람의 지속적인 존재 여부는 YOLO의 `person` 탐지 결과로 판단한다.
- `EVT:PIR:0`만으로 추론을 즉시 중지하지 않는다. 사람이 가만히 있으면 PIR이 LOW가 될 수 있기 때문이다.
- 한 프레임의 사람 미탐지만으로 추론을 중지하지 않는다. 가림이나 순간적인 모델 누락을 고려해 유예 시간을 둔다.

## 2. PIR이 판단할 수 있는 것

PIR은 사람의 신원이나 물체 종류를 인식하지 않는다. 주변의 적외선 열 분포가 변했는지를 감지한다. 체온을 가진 사람이 움직이면 쉽게 반응하므로 흔히 사람 감지 센서라고 부르지만, 실제 역할은 움직임 감지에 가깝다.

PIR만으로는 다음 항목을 판단할 수 없다.

- 감지 대상이 사람인지, 동물인지 또는 다른 열원인지
- 사람이 몇 명인지 또는 누구인지
- 사람이 가만히 있는 상태로 계속 존재하는지

햇빛, 히터, 에어컨 바람, 반려동물처럼 열 분포를 바꾸는 요소도 PIR을 동작시킬 수 있다. 반대로 사람이 가만히 있으면 PIR 출력이 LOW로 바뀔 수 있다. 따라서 PIR의 LOW는 `사람 없음`이 아니라 `현재 감지되는 열 변화 없음`을 의미한다.

### PIR 이벤트 값

| 이벤트 | 센서 출력 | 의미 |
|---|---|---|
| `EVT:PIR:1` | HIGH | 움직임 감지 시작 |
| `EVT:PIR:0` | LOW | 움직임 감지 종료 또는 현재 열 변화 없음 |

이벤트는 상태가 바뀔 때 한 번 전송한다. HIGH를 유지하는 동안 `EVT:PIR:1`을 계속 반복 전송하지 않는다.

## 3. 구성요소별 책임

| 구성요소 | 책임 |
|---|---|
| PIR 센서 | 주변 적외선 변화 감지, HIGH/LOW 출력 |
| STM32 #1 | PIR 입력을 50ms 동안 확인한 후 `EVT:PIR:1` 또는 `EVT:PIR:0` 전송 |
| Jetson 통신 계층 | STM32 이벤트 수신 및 추론 제어 계층으로 전달 |
| YOLO | 영상에서 실제 `person` 클래스 탐지 |
| 추론 제어 계층 | PIR 상태와 최근 사람 탐지 시간을 조합해 추론 상태 결정 |

PIR은 빠르고 가벼운 1차 신호를 제공하고, YOLO는 실제 사람인지 확인하는 2차 판단을 담당한다. 이 역할 분담을 통해 Jetson이 불필요한 상황에서 계속 무거운 추론을 수행하는 시간을 줄인다.

## 4. 사람 탐지 모델과 데이터 구성

COCO 기반 모델은 다양한 환경의 일반적인 `person` 특징을 이미 학습한 모델이다. 여기에 실제 설치 장소에서 수집한 데이터를 추가하면 일반적인 사람 특징을 유지하면서 프로젝트 환경의 카메라 각도, 거리, 조명과 가림 조건을 보강할 수 있다.

추가 데이터에는 다음 상황을 포함하는 것이 좋다.

- 밝은 환경과 어두운 환경
- 카메라에서 가까운 사람과 먼 사람
- 신체 일부만 보이거나 물체에 가려진 사람
- 사람이 없는 실제 배경
- 가방, 옷, 의자처럼 사람으로 오인하기 쉬운 물체

PIR 오감지는 YOLO의 사람 확인으로 걸러내고, PIR이 놓치는 정지 상태의 사람은 YOLO의 지속적인 프레임 분석으로 보완한다.

### 사람 confidence 판단 기준

YOLO의 confidence는 실제 확률과 완전히 같은 값이 아니므로 한 개의 고정 임계값만으로 사람 상태를 켜고 끄지 않는다. 사람 상태 진입 기준과 유지 기준을 다르게 두는 hysteresis를 사용한다.

| 항목 | 초기값 | 의미 |
|---|---:|---|
| 모델 출력 최소 confidence | 0.40 | 이 값보다 낮은 탐지 결과는 후속 판단에서 제외 |
| 사람 상태 진입 기준 | 0.55 | 새 사람으로 확정할 때 사용하는 기준 |
| 진입 확인 프레임 | 최근 5프레임 중 3프레임 | 한 프레임의 오탐으로 `ACTIVE`가 되는 것을 방지 |
| 사람 상태 유지 기준 | 0.40 | 이미 확인한 사람을 조명·자세 변화로 너무 빨리 놓치지 않기 위한 기준 |
| 사람 미탐지 유예 시간 | 10초 | 마지막 유효 사람 탐지 후 종료 판단까지 기다리는 시간 |

모델 추론 단계의 최소 confidence는 유지 기준과 같은 0.40으로 둔다. 모델 단계에서 0.55 또는 0.60으로 결과를 먼저 제거하면 유지 판단에 필요한 0.40~0.54 결과를 받을 수 없다.

```text
IDLE 또는 SEARCHING
→ confidence 0.55 이상이 최근 5프레임 중 3프레임
→ 사람 있음 확정, ACTIVE

ACTIVE 또는 GRACE
→ confidence 0.40 이상 person 재탐지
→ 마지막 사람 탐지 시간 갱신, ACTIVE 유지

confidence 0.40 이상 person이 10초 동안 없음
AND PIR이 LOW
→ IDLE
```

진입 기준보다 유지 기준을 낮게 두면 confidence가 임계값 주변에서 변할 때 상태가 반복해서 켜지고 꺼지는 현상을 줄일 수 있다.

### confidence 조정 방법

초기값은 실제 설치 환경의 검증 영상으로 조정한다. 밝고 어두운 환경, 거리 차이, 앉거나 일부 가려진 사람, 빈 방, 가방·의자·옷처럼 사람으로 오인하기 쉬운 물체를 포함한다.

1. 같은 검증 영상에서 confidence 기준을 0.30부터 0.80까지 0.05 간격으로 비교한다.
2. 실제 사람을 놓친 횟수와 사람 아닌 물체를 사람으로 판단한 횟수를 각각 기록한다.
3. 사람 존재 제어에서는 실제 사람을 놓치지 않는 recall을 먼저 확보한다.
4. 오탐은 최근 5프레임 중 3프레임 조건과 PIR 상태를 함께 사용해 줄인다.
5. 선택한 값은 실제 Jetson 성능과 카메라 위치에서 다시 검증한다.

## 5. 추론 상태

| 상태 | 설명 |
|---|---|
| `IDLE` | 프레임 추론을 실행하지 않고 PIR 시작 이벤트를 기다리는 상태 |
| `SEARCHING` | PIR 움직임을 받은 뒤 실제 사람이 있는지 YOLO로 확인하는 상태 |
| `ACTIVE` | YOLO가 사람을 탐지하고 있으며 추론을 계속하는 상태 |
| `GRACE` | 사람이 잠시 탐지되지 않아 종료 여부를 확인하는 유예 상태 |

모델과 카메라는 가능하면 초기화된 상태로 유지하고, `IDLE`에서는 프레임 추론 호출만 멈춘다. 모델을 매번 다시 불러오면 재시작 시간이 길어질 수 있다.

## 6. 상태 전환 규칙

| 현재 상태 | 조건 | 다음 상태 | 동작 |
|---|---|---|---|
| `IDLE` | `EVT:PIR:1` 수신 | `SEARCHING` | 다음 프레임부터 YOLO 추론 시작 |
| `SEARCHING` | 사람 탐지 | `ACTIVE` | 마지막 사람 탐지 시간 갱신 |
| `SEARCHING` | 사람 미탐지 상태가 제한 시간 동안 지속되고 PIR이 LOW | `IDLE` | 프레임 추론 중지 |
| `ACTIVE` | 사람 탐지 유지 | `ACTIVE` | 마지막 사람 탐지 시간 계속 갱신 |
| `ACTIVE` | 사람 미탐지 | `GRACE` | 추론을 유지하며 유예 시간 시작 |
| `GRACE` | 사람 재탐지 | `ACTIVE` | 종료 취소, 마지막 사람 탐지 시간 갱신 |
| `GRACE` | `EVT:PIR:1` 수신 | `SEARCHING` | 움직임을 다시 확인하며 추론 유지 |
| `GRACE` | 사람 미탐지 시간이 제한값 이상이고 PIR이 LOW | `IDLE` | 프레임 추론 중지 |

`EVT:PIR:0`은 현재 움직임 상태를 LOW로 갱신하는 이벤트다. 이 이벤트 자체는 상태를 즉시 `IDLE`로 바꾸지 않는다.

다음 조건을 모두 만족할 때만 추론을 중지한다.

```text
PIR 상태가 LOW
AND
YOLO가 제한 시간 동안 사람을 연속으로 탐지하지 못함
```

사람이 가만히 있어 PIR이 LOW가 되더라도 YOLO가 사람을 계속 탐지하면 마지막 사람 탐지 시간이 갱신되므로 `ACTIVE`를 유지한다.

## 7. 시간 설정

| 항목 | 초기값 | 의미 |
|---|---:|---|
| STM32 PIR 안정화 필터 | 50ms(0.05초) | 신호 변화 후 잡음 여부를 확인하는 시간 |
| PIR 모듈 `TIME` | 가능한 최소값, HC-SR501 기준 약 3초 | 센서가 마지막 움직임 후 HIGH를 유지하는 시간 |
| YOLO 사람 확인/미탐지 제한 시간 | 초기값 10초 | 사람 확인 실패 또는 마지막 사람 탐지 후 추론 중지를 결정하기 전 기다리는 시간 |

위 값은 초기 테스트 기준이다. 실제 카메라 위치, 조명, 사람의 이동 속도와 PIR 모듈 특성을 확인한 뒤 조정한다.

추론 재시작 시간은 다음 요소의 합으로 결정된다.

```text
STM32 안정화 50ms
+ UART 이벤트 전달 시간
+ Jetson의 다음 프레임 추론 시간
```

모델과 카메라를 유지하면 별도의 모델 로딩 시간 없이 추론을 재개할 수 있다.

### 세 시간값의 차이

- `50ms`: STM32 코드의 신호 안정화 필터다. PIR이 사람을 감지 상태로 유지하는 시간이 아니다.
- PIR 모듈 `TIME`: 실제 센서 출력이 마지막 움직임 후 HIGH를 유지하는 하드웨어 시간이다.
- YOLO 미탐지 제한 시간: Jetson이 순간적인 사람 미탐을 허용하는 소프트웨어 유예 시간이다.

마지막 움직임 이후 실제 추론 종료까지는 PIR 모듈의 HIGH 유지 시간과 YOLO 미탐지 제한 시간이 함께 영향을 준다.

## 8. PIR 모듈 권장 설정

HC-SR501을 사용하는 경우 초기 설정은 다음과 같이 잡는다.

| 항목 | 권장 초기 설정 | 이유 |
|---|---|---|
| `TIME` | 가능한 최소, 약 3초 | 사람 존재 판단을 YOLO가 담당하므로 PIR 출력 유지 시간을 길게 둘 필요가 없음 |
| Trigger jumper | `H` 반복 감지 | 움직임이 이어지는 동안 HIGH를 갱신 |
| `SENS` | 중간값 | 실제 설치 거리에서 오감지와 미감지를 비교하며 조정 |

일반적으로 `TIME` 가변저항은 반시계 방향으로 돌리면 짧아지고 시계 방향으로 돌리면 길어진다. 모듈 배치와 제조사에 따라 방향이 다를 수 있으므로 보드의 `TIME` 표시와 실제 측정 결과를 우선한다.

조정할 때는 `EVT:PIR:1`이 나온 뒤 움직임을 멈추고 `EVT:PIR:0`이 나올 때까지 시간을 측정한다. 목표 시간보다 길면 `TIME`을 조금 줄이고 다시 측정한다.

## 9. 예외 상황 처리

### 사람이 가만히 있는 경우

PIR이 LOW가 되어도 YOLO가 사람을 계속 탐지하면 `ACTIVE`를 유지한다.

### YOLO가 순간적으로 사람을 놓치는 경우

한두 프레임의 미탐으로 중지하지 않고 `GRACE`에서 10초 동안 재탐지를 기다린다.

### PIR이 사람 이외의 움직임을 감지한 경우

`SEARCHING`에서 YOLO가 사람을 확인하지 못하고 PIR도 LOW가 되면 제한 시간 후 `IDLE`로 돌아간다.

### 사람이 가려지는 경우

가림 시간이 유예 시간보다 길면 추론이 중지될 수 있다. 실제 테스트에서 문제가 확인되면 유예 시간을 늘리거나 저주기 확인 추론을 별도 정책으로 검토한다.

## 10. 전체 동작 예시

### 사람이 들어오는 경우

```text
IDLE
→ PIR 움직임 감지
→ EVT:PIR:1
→ SEARCHING, YOLO 추론 시작
→ person 탐지
→ ACTIVE
```

### 사람이 가만히 있는 경우

```text
PIR이 LOW로 변경
→ EVT:PIR:0
→ YOLO는 person을 계속 탐지
→ ACTIVE 유지
```

### 사람이 나가는 경우

```text
마지막 person 탐지
→ YOLO person 미탐지
→ GRACE
→ PIR도 LOW이고 미탐지 10초 경과
→ IDLE, 프레임 추론 중지
```

### PIR이 오감지한 경우

```text
EVT:PIR:1
→ SEARCHING
→ YOLO가 person을 확인하지 못함
→ PIR LOW와 미탐지 제한 시간 충족
→ IDLE 복귀
```

### 추론을 다시 시작하는 경우

```text
IDLE에서 새 EVT:PIR:1 수신
→ 모델과 카메라는 다시 불러오지 않음
→ 다음 프레임부터 YOLO 추론 재개
```

## 11. 확인 시나리오

| 확인 | 입력·상황 | 예상 결과 |
|---|---|---|
| □ | `IDLE`에서 PIR 움직임 감지 | `EVT:PIR:1` 수신 후 `SEARCHING`으로 전환 |
| □ | `SEARCHING`에서 사람 탐지 | `ACTIVE`로 전환 |
| □ | 사람이 가만히 있어 PIR이 LOW, YOLO는 사람 탐지 | `ACTIVE` 유지 |
| □ | YOLO가 사람을 한두 프레임 놓침 | 즉시 중지하지 않고 `GRACE` 유지 |
| □ | 사람이 다시 탐지됨 | `ACTIVE` 복귀 |
| □ | PIR LOW와 사람 미탐지가 10초 이상 지속 | `IDLE` 전환 및 프레임 추론 중지 |
| □ | `GRACE` 중 새 PIR 움직임 감지 | 추론을 중지하지 않고 `SEARCHING`으로 전환 |
| □ | PIR 오감지 후 사람이 확인되지 않음 | 제한 시간 후 `IDLE` 복귀 |
| □ | confidence 0.55 이상이 한 프레임만 발생 | 사람 있음으로 확정하지 않음 |
| □ | confidence 0.55 이상이 최근 5프레임 중 3프레임 | `ACTIVE`로 전환 |
| □ | `ACTIVE`에서 confidence가 0.40~0.54로 내려감 | 마지막 사람 탐지 시간을 갱신하고 `ACTIVE` 유지 |
| □ | confidence 0.40 이상 사람이 10초간 없고 PIR도 LOW | `IDLE`로 전환 |

### STM32와 PIR 단독 확인

1. USB Serial을 115200 baud, 8N1로 연다.
2. `PING`을 보내 `OK:PING` 응답을 확인한다.
3. PIR 앞에서 움직여 `EVT:PIR:1`을 확인한다.
4. 움직임을 멈추고 센서 `TIME` 이후 `EVT:PIR:0`을 확인한다.
5. HIGH를 유지하는 동안 같은 이벤트가 중복 전송되지 않는지 확인한다.

## 12. 구현 상태

- STM32 #1은 PIR 입력의 HIGH/LOW 변화를 `EVT:PIR:1`과 `EVT:PIR:0`으로 전송한다.
- Jetson의 상태 관리와 추론 시작·중지 정책은 이 문서를 기준으로 구현 및 검증한다.
- 사람 탐지 confidence는 진입 0.55, 유지 0.40, 최근 5프레임 중 3프레임, 미탐지 유예 10초를 초기값으로 사용한다.
- confidence 기준과 실제 유예 시간은 현장 테스트 후 최종 확정한다.
