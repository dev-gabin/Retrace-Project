# Retrace 추론·기록 정책

소스 확인 기준: 2026-10-13, `main`의 Python 애플리케이션과 MCU 펌웨어. 아래 값은 코드에 선언된 설정이며 설치 환경의 실측 성능과 구분합니다.

## 1. 구성요소의 역할

| 구성요소 | 역할 |
|---|---|
| PIR①·STM32 메인 유닛 | 움직임의 시작·종료를 USB 이벤트로 전달 |
| OpenCV | 웹캠 프레임 수집, 목격 사진에 박스 표시, JPEG 인코딩 |
| YOLO | 물건 종류·신뢰도·바운딩 박스·중심 좌표 추출 |
| `StableObjectTracker` | 저장 후보의 인식 안정성·이동·저장 간격 판단 |
| `LastSeenStore`·C TCP 서버 | 사진 공개, DB 저장 요청·조회 |
| PIR②·현관 노드 | 별도의 외출 확인 이벤트 전달 |
| `LeaveVerifier` | 외출 등록 물건을 새로운 영상에서 재확인 |

PIR은 적외선 변화에 따른 움직임 센서이며 물건의 종류를 식별하지 않습니다. 현재 추론 시작·종료는 PIR① 이벤트로 결정하며, YOLO의 사람 탐지를 진입 조건으로 사용하지 않습니다.

## 2. 카메라와 추론 상태

기준: [jetson_app.py](../jetson_nano/vision/jetson_app.py).

모델과 카메라는 시작할 때 한 번 초기화합니다. 카메라 프레임은 대기 상태에서도 읽으며, 조건에 따라 YOLO 호출을 생략합니다.

| 현재 상태 | 조건 | 다음 상태 |
|---|---|---|
| `IDLE` | `EVT@PIR:1` | `ACTIVE`, 물건 추론 시작 |
| `ACTIVE` | `EVT@PIR:0` | `GRACE`, 추론 유지 |
| `GRACE` | `EVT@PIR:1` | `ACTIVE`, 종료 유예 취소 |
| `GRACE` | PIR LOW 이후 10초 경과 | `IDLE`, 일반 관찰 추론 중지·연속 인식 횟수 초기화 |

PIR LOW는 현재 감지되는 움직임이 없다는 뜻이며 사람이 없음을 보장하지 않습니다. 현재 코드에는 `SEARCHING` 상태나 사람 탐지 기반 confidence hysteresis가 없습니다.

현관 재확인 중에는 `IDLE`에서도 YOLO를 실행할 수 있습니다. 이때 재확인 결과를 수집하며, 일반 물건 저장은 `ACTIVE`/`GRACE`에서 진행합니다.

## 3. 모델과 물건 ID

| 항목 | 현재 값 |
|---|---|
| 모델 | `jetson_nano/models/yolo/coco83_yolo26n_v6_demo_desk.pt` |
| 구성 | COCO 기본 80개 + `car_key`·`wallet`·`earphones` |
| 추론 최소 confidence | 0.50 |
| 추론 이미지 크기 | 640 |
| 장치 선택 | `detector.py`의 `device=0`, Jetson GPU 대상 |
| 카메라 인덱스 | 0 |

`detector.py`는 모델 이름을 영문 소문자·숫자·밑줄의 ID로 변환합니다. 같은 클래스 물건이 여러 개면 해당 클래스의 마지막 기록 하나를 관리하며 개체·소유자를 구분하지 않습니다.

`person`은 탐지 결과에 포함될 수 있지만 기록 필터에서 제외합니다. 모델의 confidence는 판단용 점수이며 실제 정답 확률과 동일하다고 단정하지 않습니다.

## 4. 저장 조건

기준: [object_tracker.py](../jetson_nano/vision/object_tracker.py) 및 호출부.

| 조건 | 현재 값·동작 |
|---|---|
| 기록 confidence | 0.60 이상, `person` 제외 |
| 동일 종류의 복수 탐지 | 가장 높은 confidence의 탐지 하나 선택 |
| 위치 안정성 | 이전 중심점과 30px 이내인 연속 탐지 |
| 연속 인식 | 애플리케이션에서 `stable_frames=2`로 호출 |
| 새 기록 후보 | 아직 저장하지 않았거나 마지막 저장 위치에서 10px 이상 이동 |
| 저장 시도 간격 | 동일 클래스의 직전 시도부터 5초 이상 |

위 조건을 모두 만족한 후보만 저장을 시도합니다. 클래스의 기본 `stable_frames=3`과 실제 호출값 2를 혼동하지 않습니다. 5초는 저장 시도 사이의 최소 간격이며 모든 물건을 고정 주기로 갱신한다는 뜻이 아닙니다.

성공한 저장만 `mark_saved()`로 위치를 확정합니다. 미탐지 시 연속 인식 횟수는 초기화하지만 DB의 이전 기록은 지우지 않습니다. 가려진 물건의 현재 위치를 새로 알아내는 것이 아니라 마지막 관측 정보를 유지합니다.

## 5. 사진·DB 저장과 실패 처리

Python은 저장용 프레임 복사본에 해당 물건의 박스·이름을 표시하고 JPEG로 인코딩합니다. 임시 파일 기록·동기화·이름 교체로 사진을 공개한 뒤 C TCP 서버에 메타데이터를 보냅니다.

| 상황 | 처리 |
|---|---|
| JPEG 인코딩·파일 공개 실패 | DB 저장 요청으로 넘어가지 않음 |
| DB 저장 성공 | 새 사진·기록 사용, 이전 사진은 저장 계층에서 정리 |
| 확정된 저장 오류·과거 시각 | Python은 새 미참조 사진을 정리, 기존 기록 유지 |
| 통신 오류·커밋 결과 불확실 | 새 사진을 보존하고 오류 보고 |
| `RT_CLEANUP_PENDING` | DB 저장은 성공, 이전 파일 정리 상태를 별도 관리 |

사진 파일과 DB는 하나의 원자적 트랜잭션이 아닙니다. `rt_recover()`는 저장 작업이 멈춘 상태에서 명시적으로 실행합니다. 자세한 반환 코드와 형식은 [프로토콜](protocol.md)을 참고합니다.

## 6. 현관 외출 확인

기준: [leave_alert.py](../jetson_nano/vision/leave_alert.py).

1. LOLIN D32의 PIR② 이벤트가 C TCP 서버를 거쳐 Python으로 전달됩니다.
2. `LeaveItems`에서 웹이 저장한 외출 준비물 목록을 읽습니다. 등록이 없으면 알림을 생략합니다.
3. 관찰 공간의 새 카메라 영상으로 기본 3초 동안 등록 물건을 확인합니다.
4. confidence 0.50 이상 탐지가 서로 다른 프레임에서 3회 이상 확인된 물건을 알림 대상으로 삼습니다.
5. 확인된 이름으로 ntfy 알림을 보내고 현관 노드에 `LIGHT:ALERT`를 요청합니다. 없으면 알림을 생략합니다.

| 환경 변수 | 기본값 |
|---|---:|
| `RETRACE_LEAVE_CHECK_SECONDS` | 3.0초 |
| `RETRACE_LEAVE_CHECK_CONFIDENCE` | 0.50 |
| `RETRACE_LEAVE_CHECK_HITS` | 3 |
| `RETRACE_LEAVE_ALERT_COOLDOWN` | 15초 |
| `RETRACE_ENTRANCE_CLIENT_ID` | `ENTRANCE` |

재확인은 과거 Last Seen만 보고 판단하지 않습니다. 카메라가 현관을 보는 것이 아니라 PIR②를 계기로 관찰 공간을 확인하는 구조입니다. 미확인은 물건이 반드시 사용자에게 있다는 보장이 아닙니다. 같은 외출 이벤트는 기본 15초 동안 중복 처리를 제한합니다.

## 7. SOS와 LCD

SOS 이벤트는 외출 재확인을 거치지 않고 ntfy에 전달합니다. 같은 발신자의 연속 SOS는 기본 15초 동안 제한하며, 휴대폰의 소리·TTS는 앱과 자동화 설정에 따릅니다.

LCD는 기록을 생성하지 않고 `/api/items`를 기본 10초마다 조회합니다. LCD 조회 주기, 카메라 추론 상태, 물건 저장 시도 간격은 서로 다른 설정입니다.

## 8. 확인 방법

- PIR① ON → `ACTIVE`, OFF → `GRACE`, 10초 후 `IDLE` 로그 확인.
- 안정성·confidence·이동 조건을 만족할 때만 `[SAVED]`가 나오는지 확인.
- 물건을 가려도 기존 사진과 시각이 유지되는지 확인.
- `IDLE`에서 PIR② 이벤트 후 등록 물건이 보일 때만 외출 알림이 나오는지 확인.
- SOS는 별도 경로로 전달되고 LCD는 조회만 하는지 확인.

실제 결과와 설치별 보정값은 [통합 체크리스트](classroom_test_checklist.md)에 기록합니다. 기존 기록의 빈 체크 항목을 실행 없이 통과로 바꾸지 않습니다.
