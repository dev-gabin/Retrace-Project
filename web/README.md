# Retrace 웹 화면

정적 HTML/CSS/JavaScript로 구성한 물건 조회·장치 제어 화면입니다. 기본 모드는 **실제 서버 `live`**이며 Jetson의 Python 애플리케이션이 웹 파일과 HTTP API를 같은 주소에서 제공합니다.

## 기능

- 모델·DB가 반환하는 물건 목록, 한국어 이름 검색, 마지막 사진·시각 확인 및 확대.
- 기록된 카메라 좌표로 레이저 안내 요청.
- 서랍 1~6 열기, 물건의 수동 서랍 보관 등록, 이름을 입력한 임의 물건 등록.
- 외출 전에 확인할 물건 목록 저장. 현관 재확인과 LCD가 같은 목록을 사용.
- 실제 연결 오류·응답 형식 오류·시간 초과 표시. 실패 시 샘플 모드로 자동 전환하지 않음.

목록은 차키·지갑·이어폰 세 가지로 제한하지 않습니다. 일반 YOLO ID와 `custom_...` 수동 등록 ID도 처리합니다. Last Seen은 과거 관측 정보이며 현재 위치를 보장하지 않습니다.

## 실행

### Jetson 통합 화면

1. [서버 안내](../jetson_nano/server_jetson/README.md)에 따라 C TCP 서버·DB·서랍 중계를 준비합니다.
2. 환경 변수를 읽고 `python jetson_nano/main.py`를 실행합니다.
3. PC·휴대폰에서 `http://<Jetson-IP>:8080/`을 엽니다. `RETRACE_HTTP_PORT`를 바꿨다면 해당 포트를 사용합니다.

웹 파일·API·목격 사진이 같은 origin에서 제공됩니다. LCD도 이 HTTP 주소를 사용하며 별도의 LCD 서버는 없습니다.

### PC에서 화면만 확인

Node.js 20 이상을 사용하는 예시입니다. 외부 프런트엔드 패키지 설치나 빌드가 필요하지 않습니다.

```powershell
node web/dev-server.mjs
```

`http://127.0.0.1:5173/`에 접속합니다. 이 서버는 정적 화면 확인용이며 실제 API를 구현하지 않습니다. 기본 `live` 상태에서는 API가 없어 오류가 표시될 수 있습니다. 샘플을 보려면 `config.js`의 `mode`를 의도적으로 `demo`로 바꾼 뒤 실제 사용 전 `live`로 복원합니다.

`PORT` 환경 변수로 정적 서버 포트를 바꿀 수 있습니다. `file://`로 직접 열면 모듈 로딩 문제가 생길 수 있으므로 HTTP로 확인합니다. 현재 API는 다른 origin의 CORS 연결을 제공하지 않으므로 실제 장치 연동은 Jetson이 제공하는 화면에서 수행합니다.

## 파일 역할

| 파일 | 역할 |
|---|---|
| `index.html` / `styles.css` | 화면 구조·PC/휴대폰 레이아웃 |
| `app.js` | 검색·선택·제어·등록·상태·오류 표시 |
| `api.js` | HTTP 요청·응답 검사·타임아웃·샘플 모드 |
| `config.js` | `live`/`demo`, API 기본 주소, 8000ms 요청 제한 |
| `demo-data.js` / `assets/demo-scene.svg` | 실제 관측과 구분되는 샘플 자료 |
| `dev-server.mjs` / `package.json` | 로컬 정적 서버·선택적 `npm start` |

## API와 장치 응답

요청·JSON·오류 형식은 [통신 프로토콜](../docs/protocol.md)의 HTTP API 절을 기준으로 합니다.

| 용도 | API |
|---|---|
| 목록·상세 | `GET /api/items`, `GET /api/items/{item}` |
| 사진 | `GET /snapshots/{file}` |
| 레이저 | `POST /api/items/{item}/aim` |
| 서랍 열기 | `POST /api/drawers/{n}/open` |
| 기존 물건 서랍 등록 | `POST /api/items/{item}/drawer` |
| 임의 물건 등록 | `POST /api/drawer-items` |
| 외출 준비물 | `GET` / `POST /api/leave-items` |

레이저는 웹 버튼 요청에만 반응합니다. 저장 좌표가 없거나 서랍 보관 상태면 안내하지 않습니다. 연결·보정 오류도 표시하며 현관 알림은 레이저를 자동으로 켜지 않습니다.

수동 서랍 등록은 카메라 관측과 별개입니다. 등록된 물건은 사진·좌표 대신 서랍 정보로 안내하며, 서랍 열기 후 새 관측 전에는 예전 좌표로 레이저를 안내하지 않습니다. 복귀는 서보 팔 복귀이고 서랍은 사용자가 닫습니다.

레이저 성공 응답은 Python의 USB 명령 시퀀스 반환 기준, 서랍 성공 응답은 C 서버의 명령 중계 기준입니다. 실제 물건을 찾았는지·서랍이 열렸는지는 시연과 실물 검증으로 확인합니다.

휴대폰의 외출·SOS 알림은 웹 화면과 별도로 ntfy를 통해 전달합니다. 현재 저장소의 화면에는 Service Worker·웹 푸시·PWA 설치 기능이 없습니다.

## 확인 항목

- 목록·검색·상세·사진 확대·사진 없는 기록 처리.
- 서랍 번호: 정면 기준 위 `1 2`, 가운데 `3 4`, 아래 `5 6`.
- 준비물 저장·전체 해제 후 현관 재확인 및 LCD 조회에 반영.
- 임의 이름 등록·서랍 열기 후 등록 상태 해제.
- 키보드 조작과 휴대폰 너비에서의 화면 넘침.
- 연결 실패를 성공이나 샘플 결과로 표시하지 않는지 확인.

실행한 항목만 [통합 체크리스트](../docs/classroom_test_checklist.md)에 기록합니다. `main`에는 개발용 자동 테스트 파일을 포함하지 않습니다.
